### Stream parsing error — root cause and generic fix (2026-11-26)
- **Cause confirmed from the client log, not guessed.** The Kilo error body (`opencode.log` L60457/L65749/L76477) is a single SSE event whose data is two `chat.completion.chunk` JSON objects joined by `\n`: the tool-call delta chunk (`finish_reason:null`) and the terminal chunk (`finish_reason:"tool_calls"`). Per SSE, two `data:` lines with no blank line between them are one event, so the client joins them and fails to JSON-parse two objects. Attribution: the provider emitted the packed pair, and the gateway's passthrough forwarded it verbatim — the client only applied the strict, correct parser.
- **Gateway identity checked.** `:20130` is this repo's binary (`/Users/natan/Development/GitHub/9router-go/9router-go`, PID 24423); the 14:20Z failure was served by it.
- **Live probes did not reproduce packing.** One 2,762-byte capture plus eight ~1 KB captures of `ocg/deepseek-v4.1-flash-free` with a `get_weather` tool all had a blank line between every event, so the packing is intermittent upstream rather than universal.
- **Fix** (`internal/proxy/sse_copy.go`): `writeEvents` tracks whether the previous relayed line was a `data:` line and inserts a blank separator before a following `data:` line that lacks one. Segment batching is preserved, so already-separated streams pay no extra allocation; blank, comment and other field lines reset or preserve the state correctly. This is generic SSE framing conformance, not a provider-specific branch.
- **Regression test** (`internal/proxy/sse_packed_data_events_test.go`): a packed tool-call + terminal pair must come out as two events, including when the boundary falls across reads (`iotest.OneByteReader`), and an already-separated pair must not gain an extra blank line. The test failed on the base code (packed stayed packed) and passes with the fix.
- **Verification**: `go test ./internal/proxy/... -count=1` → ok (all six proxy packages); `go vet ./...` → exit 0; `go test -count=1 ./...` → ok, no `FAIL`.
- **Not verified**: the live `:20130` path still runs the pre-fix binary, and restarting it is out of bounds, so the end-to-end re-capture waits for the operator to rebuild and restart. `golangci-lint` is not installed here, so the diff-scoped lint gate was not run.
- **Post-restart live verification (PID 77779, rebuilt binary)**: 12 tool-call streams on `ocg/deepseek-v4.1-flash-free` → 12 × HTTP 200, 219 SSE events, 207 JSON payloads all parsed, 0 adjacent `data:` lines, every run carried a tool call and closed with `[DONE]`. No regression. The upstream packing did not reproduce in these 12 runs, so this confirms the changed path stays correct on healthy streams; the deterministic red→green proof of the separator is `sse_packed_data_events_test.go`.
