## 2026-11-26 — Billing cost basis, Venice quota and a usage cache (uncommitted)
### Delivered in the working tree (not yet committed)
- **Cost basis split** (`internal/providers/billing.go`): spend the provider actually charges is kept apart from list-price estimate. `opencode-go`, `ollama` and `xiaomi-mimo` were landing in the wrong bucket; 7 days after the restart the instance reports metered `$0.2217`, list-price `$30.6896`, unclassified `$0` (empty bucket is the proof the classification closed).
- **Venice prices** (`internal/pricing/tables.go`, `venice_pricing_test.go`): replaced the placeholder rows with the per-model prices the operator's invoice shows, and pinned them with a table-driven regression test.
- **Venice quota** (`internal/venicebalance/balance.go`, `internal/handlers/dashboard/usage_venice.go`): balance read from the inference headers the provider already returns, with an optional ADMIN-key probe of `https://api.venice.ai/api/v1/billing/balance` when one is configured. Rejections are memoized so a key that cannot read billing is not retried on every dashboard open; the UI keeps the `diem`/`usd`/`bundled`/`earned` rows stable instead of collapsing them.
- **Usage cache** (`internal/handlers/dashboard/usage_cache.go`): 70 s memo on the dashboard usage read, invalidated when a connection's data or `updatedAt` changes. The SPA hydrates the cached payload before the refresh resolves, so revisiting the view paints immediately.
- **Cache-break diagnosis** (`internal/handlers/chat/cache_break.go`, `detail_composition.go`): bounded prefix hashes, the divergent element index and the estimated cost of the break; no record when the hit rate is high (5/5 live DeepSeek records had none at ≥94% cache).
